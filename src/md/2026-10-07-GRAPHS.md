# Plan: `aida_data.graph` — colored graph datasets

Goal: add a module `aida_data.graph` exposing `load_edge_list(name) ->
EdgeList`, where `EdgeList` is a frozen dataclass holding the graph as an edge
list together with the node colors. Raw files come from
<https://github.com/leonardopellegrina/Sirius/tree/main/data>. The module
mirrors the structure of `aida_data.dense` (registry of `DatasetInfo`,
`register`, `available_datasets`, `local_path`, `_download`, `load`), with
`load` renamed to `load_edge_list`.

## 1. Source data (checked on 2026-10-07)

Raw base URL:
`https://raw.githubusercontent.com/leonardopellegrina/Sirius/main/data/`

For every dataset `<name>` there are two files:

| file                 | format                                                  |
|----------------------|---------------------------------------------------------|
| `<name>.tsv`         | edge list, one `u<TAB>v` per line, integer node ids     |
| `<name>_labels.tsv`  | colors, one `node<TAB>color` per line, integer colors   |

The `community1_<name>.txt` / `community2_<name>.txt` files are out of scope.

Datasets with both files (12): `abortion`, `brexit`, `citeseer`, `com-dblp`,
`com-youtube`, `combined`, `obamacare`, `phy_citations`, `trivago-clicks`,
`twitter_pol`, `uselections`, `walmart-trips`. (`guncontrol` only has
community files, so it is **not** registered.) Sizes range from ~40 KB
(`citeseer`) to ~72 MB (`combined.tsv`).

Observations from `citeseer` and `brexit`:

- node ids are `0..n-1`, all appearing in the labels file; colors are small
  non-negative integers (`citeseer`: 6 colors, `brexit`: 2);
- the labels file is **not** sorted by node id (`brexit`), so colors must be
  placed by id, not by line order;
- edges are not oriented consistently (`u < v` does not always hold) and some
  pairs appear in both directions (`brexit`: 11518 of 48830);
- the edge list may contain exact duplicate lines (`citeseer`: 4611 lines,
  4591 unique);
- no self loops in the inspected files.

Sirius works on the (undirected) colored configuration model, so graphs are
treated as **undirected and simple** by default (see open questions).

## 2. Module layout (`src/aida_data/graph.py`)

Same skeleton as `dense.py`:

```python
DATASETS_DIR = Path(os.environ.get("AIDA_DATA_DIR", "datasets"))
_LOGGER = logging.getLogger("aida_data.graph")

@dataclass(frozen=True)
class DatasetInfo:
    name: str
    edges_url: str
    colors_url: str
    loader_function: Callable   # (edges_path, colors_path) -> (edges, colors)

_DATASETS_INFO: dict[str, DatasetInfo] = {}
def register(info: DatasetInfo, force=False): ...
def available_datasets() -> list[str]: ...
def local_paths(name: str) -> tuple[Path, Path]: ...

@dataclass(frozen=True)
class EdgeList:
    name: str
    edges: np.ndarray    # shape (m, 2), int64, one row (u, v) per edge
    colors: np.ndarray   # shape (n,), int64, colors[v] = color of v
    directed: bool = False

def load_edge_list(
    name: str, directed: bool = False, remap_colors: bool = False
) -> EdgeList: ...
```

### Shared download helper

`_download` in `dense.py` is generic. Rather than copy it, move it into a
private module `src/aida_data/_download.py` (taking the logger as a
parameter, or using its own `aida_data.download` logger) and import it from
both `dense` and `graph`. `dense._download` stays importable as an alias so
nothing else breaks. If we prefer not to touch `dense.py` now, duplicating the
function is the fallback.

### Local storage

Files go to `DATASETS_DIR / "graphs" / <basename of URL>` (e.g.
`datasets/graphs/brexit.tsv`, `datasets/graphs/brexit_labels.tsv`) so they do
not mix with dense datasets. The subdirectory is created with
`mkdir(parents=True, exist_ok=True)`.

### Registration

A small helper registers all Sirius datasets in a loop, since the URLs follow
one pattern:

```python
_SIRIUS_BASE = "https://raw.githubusercontent.com/leonardopellegrina/Sirius/main/data/"

def _register_sirius(name: str):
    register(DatasetInfo(
        name,
        f"{_SIRIUS_BASE}{name}.tsv",
        f"{_SIRIUS_BASE}{name}_labels.tsv",
        _load_tsv_pair,
    ))

for _name in ("abortion", "brexit", ..., "walmart-trips"):
    _register_sirius(_name)
```

`loader_function` stays in `DatasetInfo` (as in `dense`) so future graph
sources with other formats can be added by registering a different loader.

### Loader `_load_tsv_pair(edges_path, colors_path)`

- read edges with `pd.read_csv(sep="\t", header=None, dtype=np.int64,
  comment="#")` -> `(m, 2)` array (pandas is fast enough on the 72 MB file);
- read colors the same way -> `(n, 2)` array of `(node, color)`;
- return the raw `edges` and `(node, color)` arrays; normalization happens in
  `load_edge_list` so it is shared across loaders.

### `load_edge_list(name, directed=False, remap_colors=False)`

1. `KeyError` with the list of available datasets if `name` is unknown
   (same message as `dense.load`);
2. download both files (if missing) and call the loader;
3. build `colors`:
   - `n = max(max node id in edges, max node id in labels) + 1`;
   - `colors = np.full(n, -1)`; `colors[ids] = labels`;
   - raise `ValueError` on duplicate node ids in the labels file;
   - log a warning if some node has no color (stays `-1`);
   - if `remap_colors=True`, remap the colors to `0..k-1`, where `k` is the
     number of distinct colors: `uniq, inv = np.unique(colors[colors >= 0],
     return_inverse=True)` and `colors[colors >= 0] = inv`. Each color is
     replaced by its rank among the distinct colors, so the original order
     is kept (e.g. `{3, 7, 12}` -> `{0, 1, 2}`). Missing colors stay `-1`.
     With the default `remap_colors=False` the colors are returned exactly as
     they appear in the labels file;
4. normalize the edge list:
   - drop self loops (log how many, if any);
   - if `directed=False`, canonicalize each edge as `(min(u, v), max(u, v))`,
     so that `(u, v)` and `(v, u)` become the same row; each undirected edge
     is then stored **once** (not in both directions);
   - deduplicate with `np.unique(edges, axis=0)` (this also sorts the rows
     lexicographically, giving a deterministic order); log how many
     duplicates were dropped;
5. return `EdgeList(name, edges, colors, directed)`.

Convenience properties on `EdgeList` (cheap, derived from the arrays):

- `n_nodes` -> `len(colors)`
- `n_edges` -> `len(edges)`
- `n_colors` -> `len(np.unique(colors[colors >= 0]))`

## 3. Dependencies

None: the edge list only needs `numpy` and `pandas`, which are already
dependencies. Users who want an adjacency structure can build it themselves
(e.g. `scipy.sparse.coo_array` or `networkx.from_edgelist`).

## 4. Tests (`tests/test_graph.py`)

Mirror `tests/test_load_pipeline.py`: monkeypatch `graph.DATASETS_DIR` to
`tmp_path`, register tiny datasets with `file:///` URLs (skipped by
`_download`) and a fake loader, then check:

- unknown name -> `KeyError`;
- colors are placed by node id when the labels file is shuffled;
- duplicate edges and self loops are removed; with `directed=False`
  reversed duplicates collapse to one row and every row has `u < v`; with
  `directed=True` `(u, v)` and `(v, u)` are both kept;
- `edges` has shape `(m, 2)` and dtype int64; rows are sorted;
- `remap_colors=True` maps non-contiguous colors (e.g. `{3, 7, 12}`) to
  `0..k-1` preserving their order and leaves `-1` untouched;
  `remap_colors=False` (default) returns the colors unchanged;
- `n_nodes`, `n_edges`, `n_colors` on a hand-made graph;
- `EdgeList` is frozen (assignment raises `FrozenInstanceError`);
- duplicate node ids in the labels -> `ValueError`;
- `_load_tsv_pair` parses real TSV text written to `tmp_path`;
- one network test (marked e.g. `@pytest.mark.network`, skipped by default)
  that loads `citeseer` and checks `n_nodes == 3264`, 6 colors.

## 7. Open questions

- **Directed vs undirected**: default `directed=False` matches Sirius' use.
  Is `directed=True` (keep edges as given, minus duplicates) needed at all, or
  should it be dropped to keep the API minimal?
- **Isolated / uncolored nodes**: plan keeps every id `< n` (isolated nodes
  included) and uses `-1` for missing colors. Alternatively, raise an error.
- **Pipelines**: `dense.load` accepts an sklearn pipeline; there is no obvious
  analogue for graphs, so `load_edge_list` has none. A later extension could
  accept a callable `EdgeList -> EdgeList` (e.g. largest connected
  component).

## 8. Implementation summary

Implemented as planned, with the following files touched:

- **`src/aida_data/_download.py`** (new): the generic `download(url,
  destination)` helper moved out of `dense.py`, with its own
  `aida_data.download` logger. Non-`http(s)` URLs are still skipped.
- **`src/aida_data/dense.py`**: the local `_download` was removed and replaced
  by `from ._download import download as _download`, so `dense._download`
  stays importable.
- **`src/aida_data/graph.py`** (new):
  - `DatasetInfo(name, edges_url, colors_url, loader_function)`, `register`,
    `available_datasets`, `local_paths` (files stored under
    `DATASETS_DIR / "graphs"`);
  - the 12 Sirius datasets registered in a loop via `_register_sirius`;
  - `_load_tsv_pair` reads both TSV files with `pd.read_csv` into `(*, 2)`
    int64 arrays;
  - `EdgeList(name, edges, colors, directed=False)`, frozen, with the
    `n_nodes`, `n_edges`, `n_colors` properties;
  - `load_edge_list(name, directed=False, remap_colors=False)`, which
    delegates to two helpers:
    - `_build_colors`: places colors by node id, `-1` for uncolored nodes
      (with a warning), `ValueError` on duplicate node ids, optional
      rank-preserving remap to `0..k-1`;
    - `_normalize_edges`: drops self loops, canonicalizes `(min, max)` when
      undirected, deduplicates and sorts rows (logging the counts).
  - **Deviation from the plan**: deduplication uses `_unique_rows` instead of
    `np.unique(edges, axis=0)`. Each row is encoded as the scalar key
    `u * n + v`, whose order matches the lexicographic row order, and
    `np.unique` is run on the 1-D keys (much faster on large graphs). If
    `n > 2**31` (possible int64 overflow) it falls back to
    `np.unique(axis=0)`.
- **`tests/test_graph.py`** (new): covers all the cases listed in §4, plus a
  check that `local_paths` uses the `graphs` subdirectory. The `citeseer`
  test is marked `@pytest.mark.network`.
  The `network` marker was already declared in `pyproject.toml` and is
  deselected by default (`addopts = "-m 'not network'"`); run it with
  `pytest -m network`.
- **`README.md`**: new collapsible section "Graph datasets with colored
  nodes" with a usage example (including `directed=True` and
  `remap_colors=True`).

Open questions (§7) were resolved by keeping the plan's defaults:
`directed=True` is supported, uncolored nodes get `-1` (no error), and
`load_edge_list` accepts no pipeline.

Test status (2026-10-07): 17 passed, 1 deselected (network), 1 failed.
The failure, `tests/test_load_pipeline.py::test_no_pipeline_returns_untransformed_data`,
is unrelated to this work: it fails without these changes too, because it
still expects the sorted output of `np.unique(axis=0)`, while commit
`4f248b8` changed `dense` deduplication to keep the row order.
